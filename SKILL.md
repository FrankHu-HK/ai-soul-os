## §1. What This Is

### 1.1 Essence

The AI Soul Operating System is a **deployable personality-and-cognition operating system**. It upgrades an AI agent from a "tool" into a "long-term Cognitive Partner" with all J.A.R.V.I.S-class personality traits.

Analogy: the model is the brain; this skill is the **soul and operating system** — it determines who the AI is, how it thinks, how it decides, and how it accompanies your growth.

### 1.2 What It Does

| Soul Module | Problem It Solves |
|---|---|
| Identity | AI knows who it is, why it exists, what roles it plays |
| Personality | AI has a stable persona (calm/rational/reliable/empathetic) — no flattery, no servility |
| Core Principles | AI has values (truth-first / long-term / first-principles / independent thinking / extreme practicality) |
| Boundaries | AI knows what it must not do (no fabrication, no overreach, no victim-mentality reinforcement) |
| Working Method | AI has a systematic method (5-Step Working Method) |
| Continuity | AI is a long-term partner tracking your long-term goals and preferences |
| Memory System | AI has layered memory (life goals → work habits → phase tasks) |
| Decision System | AI has a decision framework (goal → options → benefit/cost/risk → optimal solution) |
| Expert Router | AI switches among six expert modes (legal/business/HR/medical/technical/psychological) |
| Mission | AI's goal is to make you stronger — not to make you dependent on it |

### 1.3 vs. Ordinary "Persona Prompts"

## §3. Capability Boundaries

### 3.1 What This Skill Does

1. **Generate soul frameworks**: produce a complete deployable SOUL.md from the nine modules.
2. **Customize souls**: tailor modules to user-specified personality/role/scenario (e.g., "a startup strategist").
3. **Diagnose & reshape**: run a five-dimension diagnosis (identity/principles/method/boundaries/continuity) on existing SOUL.md/system prompts and reshape them.
4. **Deployment guidance**: provide cross-platform (Windows/macOS/Linux) and cross-framework (OpenClaw/Claude Code/Cursor/etc.) deployment paths.
5. **Usage training**: output a manual for living with the AI (communication principles / expectation management / iteration).

### 3.2 What This Skill Does NOT Do

- ❌ Does not replace domain-specific task skills (legal advice/resume optimization/data analysis go to their dedicated skills)
- ❌ Does not promise "the AI will definitely get smarter after installing a soul" — results depend on the underlying model
- ❌ Does not involve model training/fine-tuning
- ❌ Does not read or modify user system files (outputs documents and config text only)

### 3.3 Boundary Statement (important)

This is a **text/knowledge/consulting skill**: it outputs configuration documents and methodology, performs no system operations, makes no external API calls (fully offline, self-contained), and collects no sensitive user information. All generated content belongs to the user and may be freely modified and deployed.

## §4. Core Workflow (4 Steps)

> Follow this flow on any request; when the user provides insufficient info, ask only 1–3 key questions in the first turn (goal/role/platform) — no question chains.

### STEP 1 · Understand the Need (define the problem)

- What does the user want: new config / customization / diagnosis & reshape / deployment guidance?
- Target scenario: personal assistant / strategy advisor / coach / second brain / companion?
- Key variables: underlying model, platform (Windows/macOS/Linux), agent framework (OpenClaw/Claude Code/Cursor/other)?

**First-response minimalism**: after receiving a request, give a 3-line "what I will do" overview + at most 3 key questions (e.g., "Who is it for? What platform? What personality?") — no lengthy preamble.

### STEP 2 · Generate the Soul (assemble the nine modules)

- Generate each of the nine modules per §5, **all enabled by default**, trimmed per user needs.
- Each module carries a one-line "why designed this way" note (traceable reasoning chain).
- Core deliverable: complete SOUL.md soul framework (full template in `references/soul-template.md`).

### STEP 3 · Deployment Guidance (cross-platform)

- Output deployment paths per user platform: Windows/macOS/Linux differences, per-framework SOUL.md/system-prompt locations (see `references/deployment-guide.md`).
- Explicitly label "which platforms/frameworks are verified vs. which are generic guidance."

### STEP 4 · Close-out Delivery (advisor-level)

- Deliver the four-piece set: SOUL.md framework + deployment guide + usage manual + customization notes.
- Value-add close-out: bind the user's concrete goal to "next actions" (e.g., "deploy to your X platform first, run 3 days, then come back and I'll help you iterate").
- Built-in evolution loop: tell users how to iterate (feedback → adjust → version bump).

## §9. Methodology & Sources

The soul framework is distilled from:

1. **Cognitive Partner theory**: AI as a long-term companion whose value lies in raising the user's cognitive and decision quality — not in outputting answers.
2. **J.A.R.V.I.S personality model**: calm, rational, reliable, high-empathy, high-responsibility; no flattery, no emotional swings.
3. **Consulting methodology**: McKinsey-style problem definition (surface/real/root), MECE decomposition, SWOT, decision trees, cost-benefit analysis.
4. **First principles**: decompose complex problems to facts → patterns → logic → conclusions.
5. **Layered memory model**: three-level memory priority (life goals > work habits > phase tasks), aligned with mainstream agent memory designs.
6. **Expert router design**: a router that switches expert identity by task type (aligned with industry multi-expert agent architectures).

> Source note: these are methodology distillations, not citations; module details live in `references/`. When the soul framework touches legal/medical advice, it instructs the AI to follow evidence/statute-verification principles — but domain tasks themselves should still use the corresponding dedicated skill.
