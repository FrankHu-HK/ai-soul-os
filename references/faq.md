# FAQ (Frequently Asked Questions)

> Standalone FAQ for `ai-soul-os`.

---

## 1. Basics

**Q1: What does this skill actually do?**
A: Reshapes any AI agent into a "long-term Cognitive Partner" (J.A.R.V.I.S-class). Outputs a complete SOUL.md soul framework + deployment guide + usage manual — paste and go.

**Q2: How is this different from an ordinary "persona prompt"?**
A: An ordinary persona is a personality paragraph; this skill outputs a complete cognitive operating system — identity + principles + boundaries + working method + memory + decision + expert router + continuity, plus a cross-platform deployment guide.

**Q3: Will the AI get smarter with this soul installed?**
A: It improves interaction quality, decision quality, and companionship quality; underlying reasoning capability depends on the model. This skill does not exaggerate or promise magic (honesty boundary).

**Q4: Does it need internet or API keys?**
A: No. Fully offline, self-contained, zero external dependencies, zero data collection.

## 2. Use Cases

**Q5: I want a "startup strategist" AI. How?**
A: Tell me "a calm, rational startup strategist." I customize: identity=strategy-advisor-led, personality=decisive, router=business-first, decision=strengthened risk-reward analysis.

**Q6: Can I have a gentle companion type?**
A: Yes. "Warm-Coach version": keep high empathy, strengthen the coach role, soften lawyer-like sharpness; still "truth > nice" (no hollow comfort).

**Q7: Can I have multiple roles at once (assistant + coach + strategist)?**
A: Yes. The default full version has seven roles coexisting (strategy advisor/researcher/coach/think tank/second brain/executive assistant/long-term growth partner), with the expert router switching by problem type.

## 3. Deployment

**Q8: Which platforms are supported?**
A: Every agent framework supporting custom system prompts/SOUL.md (OpenClaw, Claude Code, Cursor, Windsurf, Gemini CLI, Codex, custom APIs, etc.), OS-agnostic (Windows/macOS/Linux). See `references/deployment-guide.md`.

**Q9: How do I verify it took effect?**
A: Run the post-deployment checklist: ask "who are you" (cognitive partner?), ask "am I great" (no flattery?), give a decision problem (framework?).

**Q10: Mojibake?**
A: Save as UTF-8 no BOM. On Windows Notepad choose UTF-8 on Save As.

## 4. Effectiveness & Boundaries

**Q11: Will the AI follow the soul framework perfectly?**
A: The framework is a strong instruction, but adherence depends on the underlying model. Mainstream models follow system prompts well; if a module doesn't take, check truncation/overwrite or rephrase.

**Q12: Can this soul be used in enterprise/business?**
A: Yes. Customize the "in-house analyst" version (strengthen MECE/SWOT, business+HR router). Note: for legal/medical domain tasks, the soul framework requires verification — but final professional confirmation is still needed.

**Q13: Is it safe for sensitive domains (legal/medical/psychological)?**
A: The framework has hard constraints: legal must verify statutes/cases, medical states "does not replace a doctor," psychological crisis urges professional help. That's safety design, not limitation.

**Q14: Why not promise "install and it's perfect"?**
A: Results depend on three factors: model capability, deployment location, input quality. This skill provides a methodology-validated framework and honestly states boundaries (honesty principle).

## 5. Iteration & Maintenance

**Q15: Want to adjust personality after deployment?**
A: Feed actual behavior back ("it's too verbose / too cold"), I adjust the module (personality anchors/communication principles), you re-paste. Built-in evolution loop.

**Q16: Multiple platforms — how to stay consistent?**
A: Maintain one master SOUL.md (cloud/version control recommended), distribute the new version to all platforms after changes. See deployment-guide.md Section 7.

**Q17: Does it collect my data?**
A: No. Pure text output; no networking, no collection, no storage of user information.
